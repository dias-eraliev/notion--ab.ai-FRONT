# Техническое задание на разработку бэкенд-части системы AB.AI

## 1. Общие сведения

### 1.1 Назначение системы
Система представляет собой бэкенд-часть образовательной платформы с интегрированным ИИ-ассистентом для обучения, управления учебным процессом, HR и финансами.

### 1.2 Технический стек
- Язык программирования: TypeScript/Node.js
- Основной фреймворк: NestJS 10+
- База данных: PostgreSQL 15+
- ORM: TypeORM/Prisma
- Кэширование: Redis
- Очереди сообщений: RabbitMQ
- WebSocket: NestJS WebSockets
- Контейнеризация: Docker
- Оркестрация: Kubernetes

## 2. Роли пользователей и права доступа

### 2.1 Основные роли
Система поддерживает следующие роли пользователей с соответствующими правами доступа:

#### Администратор (ADMIN)
- Полный доступ ко всем функциям системы
- Управление пользователями и правами доступа
- Управление финансами и бюджетом
- Управление персоналом
- Доступ к системным настройкам
- Доступ к аналитике и отчетам

#### Преподаватель (TEACHER)
- Доступ к учебному журналу своих классов
- Управление расписанием своих занятий
- Создание и проверка домашних заданий
- Доступ к данным учащихся своих классов
- Управление учебными планами
- Отслеживание своих KPI и нагрузки

#### Студент (STUDENT)
- Просмотр своего расписания
- Просмотр и отправка выполненных домашних заданий
- Просмотр своих оценок и успеваемости
- Доступ к AI-чату (репетитор)
- Управление списком дел

#### Родитель (PARENT)
- Просмотр оценок и успеваемости своего ребенка
- Просмотр расписания и домашних заданий ребенка
- Отслеживание посещаемости
- Управление оплатами и финансами
- Загрузка чеков

## 3. Архитектура системы

### 3.1 Общая архитектура
Система представляет собой монолитное приложение с разделением на функциональные модули. В дальнейшем предусмотрена возможность перехода на микросервисную архитектуру.

### 3.2 Общие требования к API
- REST API с версионированием (префикс /api/v1/)
- Swagger/OpenAPI документация (@nestjs/swagger)
- Единый формат ответов API (с использованием интерсепторов)
- Обработка ошибок по стандарту RFC 7807 (с фильтрами исключений)
- Логирование всех действий (@nestjs/common)
- Метрики для мониторинга (@nestjs/terminus)

## 4. Спецификации API по модулям

### 4.1 Auth API

#### Эндпоинты:
- POST `/auth/login` - Авторизация пользователя
- POST `/auth/refresh` - Обновление токена доступа
- POST `/auth/logout` - Выход из системы
- GET `/auth/me` - Получение информации о текущем пользователе

#### DTO:
- `LoginDto`: { email: string, password: string }
- `RefreshDto`: { refreshToken: string }
- `LogoutDto`: { refreshToken: string }
- `UserDto`: информация о пользователе

### 4.2 Users API

#### Эндпоинты:
- GET `/users` - Получение списка пользователей
- GET `/users/:id` - Получение информации о пользователе
- POST `/users` - Создание пользователя
- PATCH `/users/:id` - Обновление данных пользователя
- DELETE `/users/:id` - Удаление пользователя
- POST `/users/change-password` - Изменение пароля пользователя

#### DTO:
- `CreateUserDto`: { email: string, password: string, role: UserRole, name: string, ... }
- `UpdateUserDto`: поля для обновления
- `ChangePasswordDto`: { oldPassword: string, newPassword: string }

### 4.3 Students API

#### Эндпоинты:
- GET `/students` - Получение списка студентов
- GET `/students/:id` - Получение информации о студенте
- POST `/students` - Создание студента
- PATCH `/students/:id` - Обновление данных студента
- DELETE `/students/:id` - Удаление студента
- GET `/students/:id/performance` - Получение данных успеваемости студента

#### DTO:
- `CreateStudentDto`: { name: string, surname: string, birthDate: Date, email: string, phone: string, groupId: number, parentId?: number, ... }
- `StudentDto`: полная информация о студенте
- `StudentPerformanceDto`: данные об успеваемости

### 4.4 Study Plans API

#### Эндпоинты:
- GET `/study-plans` - Получение списка учебных планов
- GET `/study-plans/:id` - Получение конкретного учебного плана
- POST `/study-plans` - Создание учебного плана
- PATCH `/study-plans/:id` - Обновление учебного плана
- DELETE `/study-plans/:id` - Удаление учебного плана
- POST `/study-plans/:id/lessons` - Добавление урока в учебный план
- GET `/study-plans/:id/lessons/:lessonId` - Получение урока
- POST `/study-plans/:id/lessons/:lessonId/homeworks` - Добавление домашнего задания к уроку

#### DTO:
- `CreateSyllabusDto`: { subject: string, description: string, teacherId: number }
- `SyllabusDto`: полная информация об учебном плане
- `CreateLessonDto`: { title: string, description: string, scheduledDate?: string, hasVideo: boolean, hasPresentation: boolean, hasTest: boolean, videoFile?: File, videoLink?: string, presentationFile?: File, testQuestions?: any[] }
- `LessonDto`: информация об уроке

### 4.5 Grades API

#### Эндпоинты:
- GET `/grades` - Получение оценок (с фильтрацией)
- POST `/grades` - Выставление оценки
- PATCH `/grades/:id` - Обновление оценки
- DELETE `/grades/:id` - Удаление оценки
- GET `/grades/statistics` - Получение статистики по оценкам

#### DTO:
- `CreateGradeDto`: { studentId: number, syllabusId: number, lessonId?: number, homeworkId?: number, value: number, type: string, comment?: string }
- `GradeDto`: информация об оценке
- `GradeStatisticsDto`: статистика по оценкам

### 4.6 Schedule API

#### Эндпоинты:
- GET `/schedule` - Получение расписания
- POST `/schedule` - Создание элемента расписания
- PATCH `/schedule/:id` - Обновление элемента расписания
- DELETE `/schedule/:id` - Удаление элемента расписания
- GET `/schedule/conflicts` - Проверка конфликтов в расписании

#### DTO:
- `CreateScheduleDto`: { day: string, startTime: string, endTime: string, classId: string, subject: string, teacherId: string, roomId: string, type: string, repeat: string, comment?: string }
- `ScheduleDto`: информация о расписании
- `ScheduleConflictDto`: информация о конфликтах в расписании

1. Для монолитного бэкенда рекомендуется:

2. Для эффективной интеграции:
   - Начать с критических модулей: авторизация, учебные планы, студенты
   - Использовать автоматическую генерацию типов из Swagger-документации бэкенда
   - Внедрять поэтапно, начиная с просмотра данных и постепенно добавляя редактирование
